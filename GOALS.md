# GOALS — текущие задачи (открыто 30.10.2026)

Контекст: цель проекта — «упаковать красивый тег в готовый бизнес»: терминал GiftTracker
как продукт на продажу. Мини-аппка (продукт) уже живая; теперь витрина и обвязка.

## 1. Косметика бота СНАРУЖИ (не мини-аппка) — P0

Бот — витрина: её видят все, кто заходит, до всякого Mini App.

- [ ] BotFather: `description` (что видно в профиле бота), `about`, `short_description`
      для каталога — RU + EN варианты, готовы к вставке (без «пустых обещаний»).
- [ ] Список команд через `/setcommands`: `/start`, `/help`, `/top`, `/alerts`,
      `/settings`, `/pro` — с короткими описаниями.
- [ ] Аватар бота (логотип уже есть: `static/logo.png`).
- [ ] `/start`: приветственное фото (logo) + короткий оффер в 2 строки + кнопка
      «Открыть терминал» (Mini App) и «Как это работает».
- [ ] Экран «Как это работает» — переписать под текущую логику (спреды
      Getgems/Portals, MRKT-автобай как ориентир выхода, алерты, чистый профит
      с комиссиями).

**Acceptance**: у бота заполнены описание/команды/аватар; новый юзер после `/start`
за 10 секунд понимает, что это и чем платно.

## 2. Админка — P1

База уже есть: `/admin` (доход по дням за 7 дней, тарифы, последние платежи),
`/grant`, broadcast-механика (`BROADCAST_DELAY_SEC`).

- [ ] Сводка одним экраном: юзеры (всего/за 7 дней), PRO (актив/истёкшие), выручка
      за 7 дней, живость сканера (heartbeat, последний скан, число сделок в БД).
- [ ] Список юзеров постранично: id, username, план, дата регистрации, кол-во алертов.
- [ ] Broadcast с подтверждением (превью + «Отправить N пользователям?»).
- [ ] Кнопка «Экспорт» — CSV юзеров/платежей в файл.

**Acceptance**: владелец в одном `/admin` видит здоровье бизнеса без SQL.

## 3. Реф система — допилить — P1

Уже есть: `/start ref_<tg_id>`, `users.referred_by`, `referral_link` +
`invited_count` в `/api/user/me`, кнопка «Поделиться» в Профиле.

- [ ] Награда за реферала: приглашённый получает +N дней PRO (или расширенный лимит
      алертов на 7 дней), пригласивший — +N дней PRO за каждого, кто доигрался до
      оплаты Stars (фиксация через `successful_payment`).
- [ ] Начисление идемпотентно (не начислять дважды за один платёж/одного юзера).
- [ ] В Профиле: «Приглашено: N · заработано дней PRO: M».
- [ ] Тесты: реф-переход, начисление, идемпотентность, дабл-клик по счёту.

**Acceptance**: реальная цепочка «пригласил → друг оплатил → обоим начислено»
проходит на тестовых юзерах и покрыта тестами.

      `crypto_payments` (идемпотентность по invoice_id), активация через ту же
      `activate_pro()`, что у Stars.
